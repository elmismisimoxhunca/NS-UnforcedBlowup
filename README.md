# Verification of OpenAI's Navier–Stokes and Euler formalizations

Independent, reproducible checking of the published
[OpenAI NavierStokesAndEuler repository](https://github.com/openai/NavierStokesAndEuler).
This repository contains verification infrastructure and factual run metadata—not
an original fluid-dynamics proof. It is not affiliated with or endorsed by OpenAI.

### What is checked

The two original configurations select four declarations:

- `Euler.euler_breakdown_R3`
- `Euler.exists_compact_smooth_euler_singularity`
- `NavierStokes.Comparator.navier_stokes_breakdown_R3`
- `NavierStokes.Comparator.navier_stokes_breakdown_periodic`

Comparator checks the supplied solutions against their **published reference
statements**, restricts axioms, and replays the proof with NanoDa and Lean's kernel.
The four `sorry` warnings in the default build occur in the reference challenge
modules; their placeholders are not accepted as solution proofs. The negative
`sorry` fixture is rejected before NanoDa, not an independent NanoDa rejection test.

The Euler statements concern **unforced** Euler. The Navier–Stokes statements
existentially quantify **external forcing** for every positive viscosity.
Acceptance here does not establish equivalence to a different formal statement,
mathematical adequacy of the reference definitions, experimental realizability,
or a Clay prize decision. Source/cache/compiler trust and the checker, operating
system and hardware assumptions described by upstream still apply.

## Reproduce

Use an unprivileged **Linux x86-64** account, Python 3.11+, Git, a working systemd
user manager and a **real terminal/PTY**. Landlock ABI 8 or newer and enforced
AF_UNIX denial are required. Provision these prerequisites explicitly:

1. The exact Lean installation identified in `verification.lock.json`; set
   `LEAN_BIN` to its `bin` directory. The runner neither installs Lean nor allows
   toolchain/manifest updates.
2. Trusted, built Landrun and NanoDa checkouts at the pinned revisions. Set
   `TOOLS` to their parent directory, with this layout:

   ```text
   TOOLS/landrun/landrun
   TOOLS/nanoda_lib/target/release/nanoda_bin
   ```

   The lock records source revisions, build-tool versions and the **reference
   executable hashes**. A different rebuild may produce different bytes; it must
   receive a separate review before a lock/receipt update. Do not bypass a hash
   mismatch, substitute a fake sandbox, or silently change pins. Tool installation
   is deliberately not automated by this repository.

From this repository, in a real terminal:

```sh
python3 scripts/verify-openai.py run \
  --checkout private/openai \
  --evidence "private/runs/$(date -u +%Y%m%dT%H%M%SZ)" \
  --lean-bin "$LEAN_BIN" \
  --tools "$TOOLS" \
  --cpus 0-7 --threads 8
```

Choose CPUs available to your account and sufficient memory/disk. No portable
runtime or memory bound is promised. For BB, launch that command in a persistent
terminal rather than a nonterminal subprocess.

The runner:

- clones the public repository and selects the exact revision if the destination
  is absent; an existing mismatched or dirty checkout is refused, never reset;
- executes the upstream cache/build commands and builds the **manifest-pinned**
  Comparator and compatible exporter;
- checks source/configuration hashes, all dependency revisions, exact tool
  binaries, and the installed Lean version;
- prints axioms for all four solution declarations;
- runs both **unmodified** configurations sequentially with real Landrun/NanoDa,
  mandatory systemd AF_UNIX restrictions, CPU affinity/quota, and a minimal child
  environment without inherited provider credentials;
- requires process exit 0, both kernel acceptance lines, and separately successful
  integrity checks, then writes a private `result.json`.

The runner refuses existing evidence directories. Commands, failures, logs and
exit receipts are retained locally. The tiny fixture outcomes in the reference
record are prior tool tests; this command reruns the two published configurations,
not those separate fixtures. No files are uploaded, committed or published.
The upstream Comparator supplies its own `--best-effort` Landrun flag; this does
not waive the required sandbox probe or imply ABI 9 enforcement on an ABI 8 host.
CPU quota/affinity are enforced even where upstream filters thread environment
variables from subprocesses.

### Inspect or re-audit without replaying kernels

```sh
python3 scripts/verify-openai.py inputs \
  --checkout private/openai --lean-bin "$LEAN_BIN" --tools "$TOOLS"

python3 scripts/verify-openai.py audit \
  --checkout private/openai --lean-bin "$LEAN_BIN" --tools "$TOOLS" \
  --evidence private/runs/EXISTING-RUN
```

For older evidence with build receipts in a separate directory, add
`--build-evidence PATH`. An audit checks actual local receipts, log markers,
source integrity and prepared executable hashes. It does **not** execute another
kernel replay or independently authenticate the origin of user-supplied logs.
Review a fresh run before manually updating the checked-in reference record.

## Lightweight validation and CI

```sh
python3 -m unittest discover -s tests -v
python3 scripts/verify-openai.py metadata
python3 scripts/check-public-tree.py --include-untracked
```

CI runs these lightweight checks. **CI does not rerun the large formalizations or
independent kernels.** Regression tests require missing/failed integrity checks,
missing kernel acceptance, wrong hashes and unsafe output paths to fail closed.
